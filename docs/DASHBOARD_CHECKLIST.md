# 관리 웹 UI·설치 화면 수동 점검 체크리스트 (M17, M23 디자인, M24 설치)

자동 테스트(`internal/httpapi/admin_test.go` 등)는 페이지 제공·CSP·CSRF·API 권한만 확인합니다. 실제 브라우저에서 화면이 동작하는지는 아래 순서로 사람이 확인합니다. 결과(브라우저·버전·날짜·통과/실패 항목)는 별도로 기록하세요.

## 준비

- [ ] 빈 테스트용 저장소 디렉터리를 만들고 `withalbum-server -init-storage` → `admin init`으로 관리자 계정 생성 (실제 사진 저장소를 쓰지 말 것)
- [ ] 콘솔에서 일반 사용자 2명 이상 생성(`admin create-user`) 또는 아래 관리자 화면에서 생성
- [ ] 서버를 loopback으로 실행(`http://127.0.0.1:<port>/`). LAN·TLS 점검은 `-tls -allow-lan` 실행 후 `https://localhost:<port>/`에서 별도로
- [ ] 점검 브라우저: macOS Safari, Chrome(가능하면 Firefox). 개발자 도구 콘솔을 열어 둘 것

## 설치 화면 시나리오 (M24, 이 Mac에서만)

테스트 전용 계정·폴더로 진행한다. 실제 사진 저장소를 쓰지 말 것. 설정 파일이 실제 위치에 써지지 않도록 `WITHALBUM_CONFIG`를 임시 파일 경로로 지정한다.

- [ ] `WITHALBUM_ROOT` 없이, 빈 작업 디렉터리에서 `WITHALBUM_CONFIG=<임시>/server.json ./withalbum-server` → 콘솔에 `SETUP: open http://127.0.0.1:8787/setup ... setup code XXXX-XXXX-XXXX`가 나온다
- [ ] `http://127.0.0.1:8787/` → `/setup`으로 이동. 코드 입력 전에는 저장장치 목록이 보이지 않는다(개발자 도구 네트워크 탭에 `/setup/api/volumes` 401만)
- [ ] 틀린 코드 → "남은 시도 N번", 다섯 번째에 잠김 안내 → 서버 재시작 후 새 코드로 진행
- [ ] 같은 Mac의 다른 이름(예: 컴퓨터 이름.local 또는 LAN IP)으로 열면 연결되지 않거나 `invalid_host`로 거부된다
- [ ] 저장장치 목록: 외장 디스크는 "권장", 이 Mac(홈 폴더)은 "시스템 디스크" 경고, 뺀 디스크·디스크 이미지(읽기 전용)는 선택 불가. 여유/전체 용량이 Finder "정보 가져오기"와 대략 같다
- [ ] 외장 디스크를 고르면 "쓰기 테스트 통과 · /Volumes/<디스크>"와 파일 시스템·마운트 표시. 다음 → "WithAlbum 폴더 만들기"를 체크해야만 "이 위치로 정하기"가 눌린다
- [ ] 폴더 만들기를 누르기 직전에 디스크를 빼면 "디스크가 연결(마운트)되어 있지 않아요" 오류, 내부 디스크의 `/Volumes`에 폴더가 생기지 않는다
- [ ] "다른 폴더 직접 입력"에 없는 경로를 넣으면 쓰기 테스트 실패, 폴더가 만들어지지 않는다
- [ ] 관리자 단계: 오른쪽 "설치 점검"에 저장장치·경로·권한·기본 설정(LAN 꺼짐)·백업 경고가 보인다. 비밀번호 11자 이하/확인 불일치는 거부
- [ ] "설치 완료하고 대시보드 열기" → 완료 화면 → "대시보드 열기" → 로그인 화면 → 방금 계정으로 로그인. 같은 탭에서 `/setup`을 다시 열면 404
- [ ] 개발자 도구 콘솔에 CSP·Trusted Types 위반이 없다. 쿠키 `withalbum_setup`은 HttpOnly·SameSite=Strict·Path=/setup이고 설치가 끝나면 지워진다
- [ ] 서버를 멈추고 다시 시작하면 설치 모드 없이 바로 정상 모드(로그에 같은 root·volume_id). 저장 폴더를 지정한 디스크를 빼고 시작하면 설치 모드가 아니라 "disk ... not exist" 종료
- [ ] 저장소만 등록하고 관리자 단계에서 서버를 멈춘 뒤 다시 시작 → 새 코드 → 관리자 단계부터 이어진다
- [ ] `-tls`로 시작하면 설치 모드가 열리지 않고 콘솔 명령 안내와 함께 종료된다
- [ ] 다크 모드·좁은 창(휴대폰 폭)에서 단계 목록·카드·버튼이 읽히고 키보드만으로 진행할 수 있다

## 공통

- [ ] 처음 접속 시 로그인 화면만 보이고 데이터가 보이지 않는다
- [ ] 틀린 비밀번호 → "아이디 또는 비밀번호가 올바르지 않습니다", 반복 실패 → 시도 제한 안내
- [ ] 로그인 후 개발자 도구 콘솔에 CSP·Trusted Types 위반 오류가 **없다**
- [ ] 쿠키: `withalbum_access`·`withalbum_refresh`는 HttpOnly, 세 쿠키 모두 SameSite=Strict (TLS에서는 Secure)
- [ ] 15분 이상 지난 뒤 동작해도 자동 갱신되어 계속 사용된다(또는 다시 로그인 화면으로 간다)
- [ ] 로그아웃 → 로그인 화면, 새로고침해도 로그인 화면
- [ ] 이름에 `<b>x</b>`, `<img src=x onerror=alert(1)>` 같은 문자열을 넣은 앨범·사용자 표시 이름이 **글자 그대로** 보이고 실행되지 않는다
- [ ] 다크 모드에서 글자가 읽힌다, 좁은 창(휴대폰 폭)에서 왼쪽 메뉴가 위쪽 가로 줄로 바뀌고 표가 가로 스크롤로 보인다
- [ ] 키보드(Tab)만으로 메뉴·버튼·입력에 이동할 수 있고 포커스 링이 보인다. 메뉴를 바꾸면 제목으로 포커스가 이동한다
- [ ] 브라우저 뒤로 가기로 이전 메뉴로 돌아간다(주소의 `#overview`, `#albums` 등)

## 일반 사용자 시나리오

- [ ] 메뉴에 "서버 관리" 묶음(저장장치·사용자·백업·복구·서버 설정)이 보이지 않는다
- [ ] 앨범 생성 권한이 없으면 "새 앨범" 입력 대신 "앨범을 만들 권한이 없어요" 안내가 보이고, 개요에 "새 앨범" 버튼이 없다
- [ ] 받은 초대가 개요에 보이고(메뉴 "내 앨범" 옆 숫자 배지) "수락" 후 내 앨범에 해당 역할로 나타난다. 이미 만료·처리된 초대 수락 → "초대 유효기간이 지났어요" 안내
- [ ] 받은 초대의 "거절"(테두리 보조 버튼) → 확인 대화상자 → 목록에서 사라지고 "OO 앨범 초대를 거절했어요." 안내. 오너의 앨범 상세 "초대 대기" 행도 사라지고, 오너가 같은 계정을 다시 초대할 수 있다
- [ ] OWNER가 아닌 앨범을 열면 "멤버 초대"·"앨범 설정"·멤버 목록이 없다. 제목 아래는 "보기 역할 · 사진 N장"처럼 내 역할부터 보인다. 보기·참여는 사진 개수와 미리보기, 업로드 전용은 "업로드 전용 역할이에요" 안내만 있고 사진·수량이 없다
- [ ] 앨범 상세의 파일 보내기 테스트: 참여·오너는 방패 아이콘과 "원본 보관됨 · 서버 SHA-256 확인", 같은 파일을 다시 보내면 "이미 이 앨범에 보관된 원본이에요", 업로드 전용은 "서버가 받았어요"(방패 없음), 보기 앨범에는 보내기 카드가 없다. 화면 어디에도 "업로드 완료"가 없다
- [ ] "기기 · 내 계정"에 내 사용자 ID와 복사 버튼이 있다(초대받을 때 앨범 오너에게 알려 주는 용도)
- [ ] 비밀번호 변경 → 다른 기기(앱·다른 브라우저)는 로그아웃, 이 브라우저는 유지
- [ ] 내 기기 목록에서 다른 기기 해지 → 해당 기기가 다음 요청에서 로그아웃. 현재 브라우저 해지 → 로그인 화면

## 앨범 오너(OWNER) 시나리오

- [ ] 내 앨범 → 앨범 → 상세: 왼쪽 메뉴 "내 앨범" 아래에 내 앨범 목록(지금 앨범은 굵게, 업로드 전용 앨범은 "(업로드 전용)"), 이동 경로 없음, 제목 아래 "사진 N장 · 멤버 N명"(영상·기타는 있을 때만, 수락 대기 있으면 "수락 대기 N명"), 방패·"보관됨" 없음, 사진 카드 오른쪽 "최근 추가순", 최근 사진 미리보기(최대 30), 오른쪽 "멤버" 카드(오너 "이름 (나)"·짙은 "오너" 태그, 멤버 "M월 D일 참여", 초대는 "초대 대기 · N일 남음")
- [ ] 멤버 초대(일반 사용자인 오너): "누구를 초대할까요"에 사용자 ID 입력만 있고 다른 계정 목록이 보이지 않는다(네트워크 탭에 `/admin/users` 호출 없음). 받는 사람의 "기기 · 내 계정"에서 복사한 ID로 초대 → 대상 계정에서 수락 가능. 없는/비활성 ID는 오류 메시지
- [ ] 멤버 초대(서버 관리자인 오너): 활성 계정 목록에서 고른다(나·비활성·로그인 불가 계정 제외). 이미 멤버는 "이미 멤버예요", 초대 대기는 "초대 대기 중이에요"로 흐리게 맨 아래에 있고 고를 수 없다
- [ ] 역할 버튼 "참여 / 보기 / 업로드 전용"(처음 선택은 "보기")과 설명이 실제 동작과 같다: 참여 계정으로 다른 사람 사진을 지울 수 없고 초대할 수 없다, 업로드 전용 계정은 자기가 보낸 사진도 목록에서 볼 수 없다
- [ ] "초대 보내기" → 버튼이 짙은 "OO 님에게 초대를 보냈어요 · 닫기"로 바뀌고 한 번 더 누르면(또는 X·Esc) 닫히며 멤버 카드에 "초대 대기" 행이 생긴다. 사람·역할을 바꾸면 다시 "초대 보내기". 초대받은 계정은 수락 전 앨범 이름·보낸 사람만 보이고 사진·멤버·수량은 보이지 않는다
- [ ] 멤버·초대 행의 "⋯" → 역할 변경·내보내기·초대 취소가 행 아래에 열린다. 초대 취소 → 대상 계정의 초대 목록에서 사라진다
- [ ] 역할 변경(보기 전용 ↔ 참여자 ↔ 업로드 전용) → 대상 계정의 다음 동작에 반영
- [ ] 내보내기 → 확인 창 → 대상 계정의 앨범 목록에서 사라진다
- [ ] 소유권 이전 → 확인 창 → 나는 참여가 되고 관리 메뉴가 사라진다
- [ ] 앨범 보관 → 이름을 정확히 입력해야만 진행, 보관 후 모든 계정의 목록에서 사라진다

## 서버 관리자(SERVER_ADMIN) 시나리오

- [ ] 사용자 관리: "사용자 추가" 대화상자(이름·아이디·임시 비밀번호 자동 생성/복사·회색 안내, 같은 너비의 취소/계정 만들기) → 일반 사용자·앨범 생성 꺼짐으로 목록에 나타나고 안내 토스트가 뜬다. 그 계정으로 임시 비밀번호 로그인 가능
- [ ] 표 열이 이름·역할·상태·기기·마지막 접속·앨범 생성 허용이다. 기기는 로그인된 기기 이름(3개 이상이면 "외 N대"), 마지막 접속은 그 기기들의 마지막 로그인·연결 갱신 시각(방금/HH:MM/어제/M월 D일, 마우스를 올리면 정확한 시각), 기기가 없으면 "—". 다른 기기로 로그인하면 다시 열었을 때 반영. 상태: 활성(회색)·정지(노란 옅은 면)·로그인 불가. 가입 요청·승인 배너는 없다
- [ ] 표의 앨범 생성 스위치(52×32) → 대상 계정의 다음 요청에 반영(앨범 만들기 표시). 관리자와 정지 계정은 스위치 비활성
- [ ] 이름(아바타·이름·아이디)을 누르면 관리 패널 → 역할·앨범 생성 권한 저장 → 대상 계정의 다음 요청에 반영
- [ ] 마지막 관리자를 강등·비활성화하려 하면 거부 메시지
- [ ] 관리 패널의 "소유 앨범"에 개수만 보이고 **앨범 이름·사진은 보이지 않는다**
- [ ] 다른 사람의 앨범은 관리자의 "내 앨범"에 나타나지 않는다(초대받지 않은 한)
- [ ] 사용 중 앨범을 가진 사용자 비활성화 → "소유한 앨범이 있어 비활성화할 수 없습니다" + 오너가 직접 이전·보관하라는 안내
- [ ] 그 사용자가 앨범을 모두 보관한 뒤: 넘겨받을 계정 선택 → "보관 앨범 N개 재배정 후 비활성화" → 계정이 비활성으로 바뀌고 그 계정의 모든 기기가 로그아웃
- [ ] 넘겨받은 계정에서도 보관 앨범이 보이지 않는다
- [ ] 다시 활성화 → 로그인 가능
- [ ] 다른 사용자의 기기 목록·해지 → 해당 기기가 로그아웃
- [ ] 저장장치: 디스크 연결·여유 공간·업로드 예약·우회 저장 차단·새 업로드·무결성·시작 시 점검 개수가 보이고 경로·볼륨 ID는 보이지 않는다
- [ ] 백업·복구: 콘솔 명령 안내만 보이고 "백업됨" 같은 상태는 표시하지 않는다
- [ ] TLS 꺼짐 안내(평문 실행) / `-tls` 실행 시 지문이 콘솔 `withalbum-server tls` 출력과 같다
- [ ] 저장장치 오류(D-03): 테스트 저장소의 `.withalbum-volume.json`을 다른 곳으로 옮기거나(또는 외장 디스크를 뺌) → 상단 칩 "저장 중단됨", 메뉴 "저장장치"에 빨간 점, 개요에 "디스크 분리" 상태 카드, 저장장치 화면에 빨간 경고·점검 결과·"다시 시작하려면" 단계. 앨범 만들기·업로드는 거부된다. "재검사" → 버튼이 "아직 연결되지 않았어요 · 다시 검사"로 바뀐다. 표식을 되돌리고 재검사 → **여전히 저장 중단**(한 번 사라진 저장소는 서버를 다시 시작해야 정상으로 돌아옴, M37) → 서버 재시작 후 정상
- [ ] 일반 사용자 계정에서도 저장 중단 시 상단 칩과 개요 상태 카드가 보인다(저장장치 메뉴는 없음)

## 디자인 시안과 나란히 비교 (M23)
