# 홈네트워크 격리 안내 (서버 Mac ↔ 홈캠·Home Assistant)

집 밖 접속(Tailscale Funnel [`FUNNEL.md`](FUNNEL.md), 중계 [`RELAY_DESIGN.md`](RELAY_DESIGN.md))을 켜면 서버의 로그인 화면은 인터넷에서 접속을 시도할 수 있게 됩니다. 서버는 인증·앨범 권한·속도 제한으로 지키지만, **서버가 뚫렸다고 가정**하고 그다음 단계(이 Mac에서 홈캠·Home Assistant·공유기 관리 화면으로 넘어가기)를 막는 것이 가장 중요한 방어층입니다. Funnel 자체는 내부망 확산을 막아 주지 않습니다.

이 문서는 일반적인 안내입니다. 공유기 메뉴 이름·지원 기능은 제품과 펌웨어마다 다르니, 자신의 공유기 설명서로 확인하세요.

## 목표

| 출발 → 목적지 | 목표 |
|---|---|
| 서버 Mac → 인터넷 | 허용 (Tailscale, 업데이트) |
| 서버 Mac → Home Assistant | **차단** |
| 서버 Mac → 홈캠·기타 IoT | **차단** |
| 서버 Mac → 공유기 관리 화면 | **차단** (관리는 다른 기기에서) |
| 서버 Mac → 다른 PC·NAS | 기본 차단, 꼭 필요한 대상만 예외 |
| 가족 앱 → Funnel → 앨범 API | 앱 인증·권한을 통과한 요청만 |

## 1. 공유기에서 망 나누기 (우선)

서버 Mac과 스마트홈 기기를 **서로 다른 네트워크**에 두고, 서버망 → 스마트홈망을 막습니다.

- **VLAN / 망 분리 기능**이 있는 공유기·스위치라면: 서버 Mac(또는 스마트홈 기기)을 별도 VLAN에 두고 VLAN 간 통신을 차단합니다. 꼭 필요한 통신만 대상·포트를 지정해 허용합니다.
- **게스트 네트워크**: 게스트 Wi-Fi를 만들었다고 격리가 됐다고 **가정하지 마세요.**
  - 많은 ipTIME 등 가정용 공유기의 게스트망은 **무선에만** 적용됩니다. **유선으로 연결한 Mac mini에는 적용되지 않을 수 있습니다.**
  - "내부망 접근 차단" 같은 옵션이 따로 있는지, 켜져 있는지 확인합니다.
  - 홈캠을 게스트 Wi-Fi로 옮기는 방법도 있지만, 앱 연동(같은 망 필요)이 깨질 수 있으니 확인 후 진행합니다.
- 하위 공유기를 하나 더 달아 이중 NAT로 만드는 것만으로는 안쪽 → 바깥쪽 사설망 접속이 막히지 않을 수 있습니다(바깥 공유기의 사설 주소로는 여전히 접속 가능). 반드시 아래 점검으로 확인합니다.

## 2. 공유기 노출 점검 (사람이 확인)

- [ ] **포트포워딩**: 위드앨범용 포트포워딩은 **필요 없습니다**. 남아 있는 규칙이 있으면 지웁니다(IPv4).
- [ ] **UPnP**: 필요 없으면 끕니다(기기가 스스로 포트를 여는 기능).
- [ ] **원격 관리(외부에서 공유기 관리 화면 접속)**: 끕니다.
- [ ] **IPv6 인바운드**: IPv6를 쓰는 경우 공유기 방화벽이 외부 → 내부 IPv6 연결을 막는지 확인합니다(IPv4 포트포워딩과 별개).
- [ ] **DMZ**: 설정되어 있지 않은지 확인합니다.
- [ ] 공유기 펌웨어 업데이트, 관리자 비밀번호 변경.

## 3. Mac 자체 방화벽 `pf` (보조 수단)

공유기에서 망을 나누기 어려우면 Mac의 `pf`로 서버 Mac → 스마트홈 기기 통신을 막아 위험을 줄일 수 있습니다. 단:

- Mac의 관리자 권한을 빼앗기면 `pf` 규칙도 바뀔 수 있어 **강한 경계가 아닙니다.** 공유기 분리가 우선입니다.
- 잘못된 규칙은 원격 접속·공유·Tailscale을 끊을 수 있습니다. **되돌리는 방법을 먼저 준비**하고, 화면·키보드가 있는 상태에서 시험하세요.

예시(사설 대역 `192.168.0.0/24`에 기기가 있고, 공유기가 `192.168.0.1`이며, DNS는 공유기를 쓴다고 가정 — 자신의 주소로 바꾸세요):

```
# /etc/pf.anchors/withalbum-isolation  (예시)
# 공유기의 DNS(53)만 허용하고, 같은 대역의 나머지 기기로 나가는 연결은 막음
pass out quick proto { tcp udp } from any to 192.168.0.1 port 53
block drop out quick from any to 192.168.0.0/24
```

적용·확인·되돌리기(시험용, 재부팅하면 사라짐):

```
sudo pfctl -a withalbum-isolation -f /etc/pf.anchors/withalbum-isolation   # 규칙 넣기
sudo pfctl -E                                                               # pf 켜기(토큰이 출력됨)
sudo pfctl -a withalbum-isolation -s rules                                  # 확인
# 되돌리기:
sudo pfctl -a withalbum-isolation -F rules                                  # 규칙 지우기
sudo pfctl -X <위에서 받은 토큰>                                              # pf 켠 것 되돌리기
```

`anchor`를 `/etc/pf.conf`에 넣어 영구 적용하는 것은 시험을 마친 뒤에, 원래 `/etc/pf.conf` 사본을 남겨 두고 하세요. 같은 대역의 공유기 관리 화면(80/443)이 막히는 것은 의도한 동작입니다.

## 4. 격리 완료 판정 (5단계)

1. **이 Mac에서 실제 홈캠·Home Assistant IP의 서비스 포트 접속이 실패**하는지 확인합니다. 메뉴 막대 앱 → **내부망 격리 점검…**에 주소를 적고 점검합니다(예: `홈캠 192.168.0.30:554`, `HA 192.168.0.40:8123`, `공유기 192.168.0.1:80`).
   - **막힘**: 2초 안에 응답이 없거나 경로가 없음 → 통과.
   - **길 열림(포트 닫힘)**: 기기가 응답했음 → 네트워크 길이 열려 있으니 **실패**로 봅니다.
   - **열림**: 접속됨 → **실패**.
   - macOS가 "로컬 네트워크" 접근을 물으면 **허용**해야 정확합니다. 거부하면 열린 기기도 "막힘(경로 없음)"으로 보일 수 있습니다(시스템 설정 → 개인정보 보호 및 보안 → 로컬 네트워크). 터미널에서 `nc -vz -G 2 192.168.0.30 554`로도 확인할 수 있습니다.
2. 스마트홈 기기가 있는 **전체 대역**에 대해 공유기·방화벽 정책을 검토합니다(점검한 기기만이 아니라).
3. **재부팅·DHCP 주소 변경·Wi-Fi↔유선 전환 뒤**에도 1번이 그대로인지 다시 점검합니다.
4. 위드앨범 업로드·다운로드, 외장 디스크, Tailscale, 필요한 관리 작업이 **정상**인지 확인합니다.
5. 필요하면 **스마트홈 쪽 → 이 Mac** 방향도 막혀 있는지 확인합니다(다른 기기에서 이 Mac의 포트로 접속 시도).

점검 결과(날짜, 대상, 막힘/열림)는 직접 기록해 두세요. 앱은 결과를 저장하거나 서버로 보내지 않습니다.

## 5. 이 Mac 자체

- 서버는 일반 사용자 계정으로 실행합니다(메뉴 막대 앱·설치 스크립트 기본). 관리자 계정으로 평소 로그인하지 않는 것이 좋습니다.
- 외장 디스크의 위드앨범 폴더 외 개인 파일을 같은 디스크에 두지 않는 것을 권장합니다.
- macOS·Tailscale·위드앨범을 주기적으로 업데이트하고, 쓰지 않는 공유 서비스(파일 공유, 화면 공유, 원격 로그인)는 끕니다.
