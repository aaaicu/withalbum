# WithAlbum Server v0.1.0-alpha.3 (prerelease)

v0.1.0-alpha.2의 **수정판**입니다. **정식판이 아닙니다.** 주의 사항은 [v0.1.0-alpha.2 릴리스 노트](v0.1.0-alpha.2.md)와 [v0.1.0-alpha.1 릴리스 노트](v0.1.0-alpha.1.md)를 그대로 따릅니다.

## 고친 것: Docker 구성에서 Google 로그인

alpha.2를 Docker Compose로 돌리면 Google 로그인이 되지 않았습니다.

- 서버에 Google 클라이언트 ID가 설정돼 있지 않아 `POST /api/v1/auth/sign-in/nonce`의 `providers`가 `["apple"]`뿐이었습니다.
- 서버 컨테이너는 바깥으로 나갈 길이 없어(의도한 격리) Google·Apple 공개 서명 키를 받을 수 없었습니다.

이번 판에서:

- 위드앨범 앱의 **공개** Google 클라이언트 ID(iOS 클라이언트, Android가 토큰을 요청하는 웹 클라이언트)를 서버에 내장했습니다. 비밀값이 아닙니다. 끄려면 `WITHALBUM_GOOGLE_CLIENT_IDS=off`.
- `compose.yaml`에 `keys` 컨테이너가 생겼습니다. `withalbum-server oidc-keys`가 정해진 두 주소에서만 공개 키를 6시간마다 받아 `oidc-keys` 볼륨에 씁니다. 서버는 그 볼륨을 **읽기 전용**으로 읽기만 하고(`WITHALBUM_OIDC_KEYS_DIR=/keys`) 외부에 묻지 않습니다. 서버와 `keys`는 네트워크를 함께 쓰지 않으므로 **서버 컨테이너의 격리(홈 네트워크·인터넷 차단)는 그대로**입니다.
- Docker가 아닌 설치(Mac·Linux 직접 실행)는 이전처럼 서버가 키를 직접 받습니다.

## 업데이트 (Docker)

사진 보관 폴더(`WITHALBUM_DATA`), TLS 키(`.system/tls/`), 연결 정보는 그대로 둡니다. `.env`도 바꿀 필요가 없습니다.

```sh
git fetch && git checkout v0.1.0-alpha.3
docker compose build
docker compose up -d                      # keys 컨테이너가 새로 생깁니다
docker compose logs keys                  # "google: updated", "apple: updated"
docker compose exec withalbum ls -l /keys # google.json, apple.json
# 격리 확인(서버 쪽은 계속 all blocked)
docker compose run --rm --no-deps withalbum reach <공유기>:80 <홈캠>:554 1.1.1.1:443
```

시작 로그에 `sign-in with Google/Apple: google, apple (linked accounts only)`와 `sign-in keys: read from /keys (no outbound request)`가 보이면 됩니다.

## 앱에서

기존 계정은 아이디·비밀번호로 로그인 → 설정 → 로그인 방법 → Google **연결**(현재 비밀번호 확인) → 이후 로그인 화면의 "Google 계정으로 로그인". Google 로그인으로 새 계정이 만들어지지는 않습니다(`identity_not_linked`). 서버가 Google을 꺼 두면 앱은 버튼 대신 안내를 보입니다(앱 0.1.0+3 이상).
