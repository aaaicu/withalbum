|---|---|---|

| 3. iCloud 우회 | iCloud Photos/공유 앨범을 Mac mini 브리지로 사용 | **폐기** (원본/계정/용량/NAS 확장 문제) |
| 4. 원본 관리 | 사용자 로컬 서버의 해시 기반 중복 제거와 원본 보관 | **유지** (CAS/메타데이터 분리) |
| 5. 저장 공간 | 업로드 후 모바일 위드앨범 앱 내 경량 프리뷰 유지, 원본 유지는 옵션 | **유지** (기본 사진 앱 원본 자동 삭제 금지) |

## 해결해야 하는 구현 상 상충점

- 현재 `server/main.go`는 JSON/해시 ID/인증 없음이지만 목표 v1.4는 SQLite/랜덤 논리 ID/ACL. 무작정 목표 DB 문서가 실제로 적용된 것처럼 취급하지 말 것.
- 과거 일반 공유 폴더에 하드링크를 직접 노출하는 아이디어는 원본 보호 위험이 있다. 보호된 pool과 안전한 Imports 분리 설계 우선.
- 과거 무음 푸시로 iOS 앱이 매번 깨어난다고 설명한 부분은 운영 보장이 없다. 동기화 재시도/수동 버튼을 기본 UX로 유지.
- 과거 Google Drive writer 권한을 앱의 세밀한 CONTRIBUTOR처럼 표현했다면 과장이다. Google의 native ACL 제약을 사실대로 고지.
- 최초 기획의 상용화 가능성 전망은 시장 검증이나 법적 판단이 아니다. 제품 품질·권리·심사는 별도 검증.
